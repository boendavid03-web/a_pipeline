# `map_empty` table navigation diagnosis

The shipped `quicktest` runs the Jackal from local `[5,5]` to `[10,5]`. The original world has `table_0` at `[7,5]`, with its physical mesh and collision shape unchanged throughout this work. Arena's asset annotation declares bounds `x ±0.88 m, y ±1.23 m, z 0–0.75 m`.

Initial RPP reached the goal, but a later collision-aware repeat recorded 232 Arena 2D footprint events against `world_table_0`; DWB recorded 526 events in one endpoint-successful run. A read-only ROS occupancy query during the original runtime found `/arena/env_0/task_generator_node/map` had value `0` (free) at map-frame table center `[12,10]`, although the Arena collision tracker knew the table. The world map renderer reads `bbox` from the world static entity, while `table_0` only had model and pose. The one-line `bbox` patch copies the existing annotated bounds into `world.yaml`. Post-patch `/map` and global costmap both report occupancy `100` at `[12,10]` (`logs/map_table_after_bbox.txt`). RPP then reached with error `0.136 m` and zero 2D events; its path stayed at least `1.38 m` from table center.

The first post-map DWB run still drove into the table and timed out. Source config showed the local costmap's `static_layer` block was defined but not in its plugin list. Added that existing layer to the list; the first attempt exposed a missing `plugin` class setting, then adding `nav2_costmap_2d::StaticLayer` loaded it. The resulting local costmap reports table center `100` after reset (`logs/local_static_layer_after_reset.txt`), but DWB still entered the table edge and timed out.

Nav2 Jazzy's `BaseObstacleCritic` checks the trajectory center point against the costmap. The shipped DWB config uses that critic. Nav2 also ships `ObstacleFootprintCritic`, which checks the robot footprint. The DWB change alters only that critic name and matching scale key while retaining the scale value and all other DWB settings. The live controller parameter confirmed `ObstacleFootprint`. One final-config run reached within 0.240 m with zero Arena 2D collision events; another ended at 0.251 m, just beyond the unchanged 0.25 m threshold, with zero events. DWB therefore remains a repeatability issue, not a claimed reliable pass.

Arena 2D footprint events are separate from PhysX contact. A zero event count demonstrates that the Arena footprint/grid checker saw no overlap; it does not alone prove zero PhysX contacts.
