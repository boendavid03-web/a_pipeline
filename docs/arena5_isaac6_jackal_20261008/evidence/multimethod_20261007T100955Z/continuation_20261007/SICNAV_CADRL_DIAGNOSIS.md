## CADRL

Original failed run: `RUNS/multimethod_cadrl_headless_20261007T104202Z_1582170`, final goal error about 6.163 m. Instrumented unchanged rerun: `RUNS/multimethod_cadrl_headless_20261007T183058Z_2400366/result.json`, timeout with 5.708 m final error and zero sampled Arena 2D events. Its native SDK trace records 1,202 active observations and 1,202 actual network inputs/actions. Every active frame carried 640 laser beams and zero pedestrians; each network state contained 2–10 laser-derived obstacle clusters, mostly 5–8. The nearest finite laser range reached 0.400 m. The policy chose negative heading changes in 1,113 of 1,202 decisions, positive in 89; the TF trajectory reached the south wall around `y=5.254` and did not turn back toward the fixed goal. Thus sensor absence and model-load failure are ruled out for this run. The exact reason for the policy preference is not proven by these traces.

The Arena wrapper's cluster radius used `clip(extent, 0.15, 1.0)`, whereas original `mit-acl/cadrl_ros/scripts/cadrl_node.py::cbClusters` uses a 0.3 m floor and 1.5 times cluster extent. Original ROS code also has separate near-goal speed control and an external obstacle/action chain; the local wrapper is a reconstruction, not a byte-for-byte launch of that ROS node. Primary source: https://github.com/mit-acl/cadrl_ros/blob/master/scripts/cadrl_node.py and https://github.com/mit-acl/cadrl_ros/blob/master/scripts/network.py . A single-variable radius candidate is saved as `cadrl.radius_candidate.patch`; it was reverted from the live planner before this report. Its bounded Isaac attempt `RUNS/multimethod_cadrl_headless_20261008T020005Z_2893608` was rejected before launch by the resource gate because UDP port 54800 in ROS domain 189 is held by `/system.slice/todeskd.service`. The attempt has no `result.json` and is **NOT_TESTED**, not a navigation failure. No process was stopped to free that port.
